# 项目文档维护规范

本文件规定项目文档的职责、更新条件和一致性要求。

## 1. 文档职责

| 文档或位置 | 维护内容 |
| --- | --- |
| `AGENTS.md` | 项目 AI 工作入口、操作边界、规则依据和验收入口 |
| `README.md` | 项目介绍、实际目录、技术基线、环境、操作命令与文档导航 |
| `docs/ENGINEERING_RULES.md` | 已确认的项目工程约束与验证要求 |
| `docs/WRITING_RULES.md` | 文档职责、维护要求和项目术语与格式 |
| `docs/CURRENT_STATE.md` | 当前实现、重要限制、实际阶段、重大偏差和有效验证依据 |
| `PROJECT_PLAN.md`（可选） | 项目目标、范围、目标架构、实施阶段和验收标准 |
| `docs/contracts/`（可选） | 已确认的业务与数据规则及边界 |
| `docs/api/`（可选） | 正式接口、参数、响应和错误契约 |
| `docs/design/`（可选） | 专项设计的目标、职责、边界、依赖和验收标准 |
| `docs/audits/`（可选） | 特定日期、范围和版本的审查或验收结论及证据 |
| `docs/archive/`（可选） | 已失效但仍有参考价值的历史文档 |

可选文档按实际内容创建，并更新 README 导航。草案明确标记为未确认，不作为正式契约依据。

## 2. 更新条件

| 实际变化 | 更新位置 |
| --- | --- |
| 已实现功能、主要结构、重要限制或实际阶段变化 | `docs/CURRENT_STATE.md` |
| 目录、环境、依赖基线或操作命令变化 | `README.md` |
| 项目范围、目标架构、阶段或验收标准正式变化 | 已存在的 `PROJECT_PLAN.md` |
| 正式业务、数据或接口规则变化 | 对应契约文档，并同步受影响的实现与测试 |
| 专项设计目标、边界、依赖或验收标准变化 | 对应 `docs/design/` 文档 |
| 工程约束或验证要求变化 | `docs/ENGINEERING_RULES.md` |
| 文档职责、术语或格式变化 | `docs/WRITING_RULES.md` |
| 项目操作边界、规则依据或读取入口变化 | `AGENTS.md` |

内部重构、变量改名、格式化及无项目级影响的小修复，通常无需更新状态或规划文档。实现偏离正式目标时，在状态文件记录重要偏差；设计文档保留目标与验收标准。

## 3. 状态与证据

- 状态文件中的核查记录包含日期、对应版本、范围、结果与证据；局部验证只支持相应范围的结论。
- 限制与验证依据只保留当前有效的内容，历史过程由版本历史、任务系统或已有审查记录保存。
- 仓库实现与部署状态分别记录；未核查部署时标记“未核查”。
- 需要保存阶段验收或重大审查证据时，按需创建有日期的审查记录。后续修复不覆盖原结论；纠错注明更正内容、日期与原因。
- 历史文档归档时注明失效原因、日期和有效替代入口，并更新导航。

## 4. 一致性检查

- 核对文档与已确认的实现、配置、契约及验证证据是否一致。
- 同一规则或命令只维护一处，其他文档引用其位置。
- 检查文件路径、相对链接、章节引用和术语是否一致。
- 当前方案变化时，更新直接相关的旧描述；没有事实变化时不改状态日期。
