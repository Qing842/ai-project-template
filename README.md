# AI 项目模板

## 0. 使用说明

本仓库提供项目约束与文档模板，用于记录项目目标、环境边界、工程规则和当前状态。

模板不包含业务代码。未填写的内容仅为占位提示，不代表已确认的项目事实。

### 获取模板

- **新项目**：点击 `Use this template` → `Create a new repository` 创建独立仓库，再克隆到本地。
- **已有项目**：在现有项目中向 AI 提供[模板仓库链接](https://github.com/Qing842/ai-project-template)，由 AI 读取五份核心文件并根据实际项目完成适配。

### 规范适配

将以下指令发送给 AI：

```text
请检查当前项目，并参考以下模板仓库完成项目规范与文档适配：https://github.com/Qing842/ai-project-template
如果当前项目已有 AGENTS.md，先读取并遵守其有效约束。
已有项目中经核实有效的工程规范和安全限制应予保留，不因模板删除或精简对应条文而自动移除。
对照模板仓库的五份核心文件逐一检查：缺失的文件按原相对路径补齐；已有文件保留有效内容，比较后合并适配，不直接覆盖。
如无法访问模板仓库或缺少关键资料，应明确说明，不得凭空生成模板规范。
先检查项目现有文件、源码与配置，再根据实际情况填写项目目标、技术栈、目录结构、环境与项目约束。
本次适配只修改项目文档；安装依赖、生成运行配置、搭建业务代码和启动服务需有对应任务授权。
没有证据的信息标记为“待确认”，不得编造。
如缺少项目目标或影响实施的关键决策，请先询问我；其他事项优先选择简单、合理、可维护的方案。
环境与外部连接未确认前，不执行存在相关副作用的操作。
未经授权，不提交、推送、合并或发布。
适配完成后，按 README 的要求清理模板说明和已完成的占位提示。
完成后说明实际修改、验证结果及仍需确认的事项。
```

### 项目适配内容

AI 根据实际项目情况完成：

1. **README.md**：填写项目介绍、技术栈、目录、环境及发布方式；按第 4 节维护实际命令或其权威文档入口。
2. **docs/CURRENT_STATE.md**：记录已确认的实现状态与待验证事项；没有业务代码时如实说明尚未实现。
3. **专项规范**：填写已确认的工程约束、文档维护要求与业务术语。
4. **AGENTS.md**：核对项目规则入口、操作边界和验收要求。

适配完成后，将 README 改为实际项目名称，删除第 0 节及已完成的模板填写提示。未核实的内容继续标记为“待确认”。

只有确有需要时才创建额外文档，不预先建立空目录。

### 文件结构

```text
项目根目录/
├── AGENTS.md                 项目 AI 工作入口与约束
├── README.md                 项目介绍与操作说明
├── PROJECT_PLAN.md           可选：项目计划
└── docs/
    ├── CURRENT_STATE.md      当前实现状态
    ├── ENGINEERING_RULES.md  项目工程约束
    ├── WRITING_RULES.md      项目文档维护规范
    ├── contracts/            可选：业务与数据契约
    ├── api/                  可选：接口契约
    ├── design/               可选：专项设计
    ├── audits/               可选：审查与验收记录
    └── archive/              可选：历史归档
```

上图的可选文件与目录仅表示推荐位置。模板默认只有五份核心文件，不要求增加固定语言目录或特定 AI 工具配置。

模板自身的维护记录与历史验收结果，请参阅 [原项目 Wiki](https://github.com/Qing842/ai-project-template/wiki)。
